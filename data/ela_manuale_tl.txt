TITLE|Manwal ng paggamit ng E-LAYER ANALYZER
SUB|Detalyadong manwal ng paggamit - inihanda ni Costantino IC8TEM - bersiyon 0.5.0, Nobyembre 2026. Ang mga numero sa loob ng square bracket ay tumutukoy sa tab na MGA SANGGUNIAN; ang mga pormula at ang mga pagpili sa kalkulasyon ay nasa tab na BUOD NG MGA PAGPILI SA KALKULASYON.
H1|1. Bago magsimula
H2|1.1 Ano ang ginagawa ng programa
P|Pinagsasama ng E-LAYER ANALYZER sa iisang programa ang mga kasangkapan para pag-aralan ang mga mode ng propagasyon sa VHF na dumaraan sa E layer ng ionosphere: ang sporadic-E, kasama ang multi-hop at ang lampas sa kontinente, ang F.A.I. (mga iregularidad na nakahanay sa magnetic field), ang meteor scatter, kasama ang nakapaloob na programang YA-MS, at ang radio aurora. Gumagana ito sa mga spot ng mga DX cluster nang real time at sa mga ADIF log, at ipinapakita ang bawat resulta sa isang mapa na sumasakop sa dalawang-katlo ng window, kasama ang data at mga kalkulasyon sa kanang ikatlong bahagi.
H2|1.2 Pag-install at ang folder ng data
P|Gumagana ang programa sa Windows (64 bit, 32 bit at ARM64), Linux (x86_64, ARM64, armv7l at Alpine), Raspberry Pi (Raspberry Pi OS na 64 at 32 bit, Slackware ARM64) at Mac (Apple Silicon at Intel); para sa FreeBSD amd64 may eksperimental na package. Dina-download ito mula sa pahinang Releases ng GitHub repository: para sa Windows may installer at portable na bersiyon sa isang .zip file; para sa Linux ang mga package na .deb, .rpm, Arch at Slackware, ang AppImage at ang mga .tar.gz archive na may installation script; para sa Mac isang .dmg image. Walang bersiyon para sa Linux i686 (mga PC na 32 bit) at OpenBSD, dahil walang .NET para sa mga sistemang iyon.
LI|Windows: inilalagay ng installer ang programa sa C:\E-LAYER-ANALYZER, katabi ang folder na data; ang portable na bersiyon ay ine-extract sa kahit anong folder at binubuksan gamit ang E-LAYER-ANALYZER.exe. Para sa mga PC na may ARM processor (Snapdragon) may mga file na -win-arm64-.
LI|Linux at Raspberry Pi: gamit ang package na .deb (sudo apt install ./e-layer-analyzer_..._amd64.deb, o _arm64.deb para sa Raspberry Pi OS na 64 bit at _armhf.deb para sa 32 bit), binubuksan ang programa mula sa menu at sa unang pagbukas ay kinokopya nito ang sarili sa ~/E-LAYER-ANALYZER; ang archive na .tar.gz (linux-x64, linux-arm64, linux-arm o linux-armv7l) ay ine-extract at pinapatakbo ang ./E-LAYER-ANALYZER, o ini-install ito ng ./installa.sh sa ~/E-LAYER-ANALYZER na may icon sa menu.
LI|Slackware (x86_64 at ARM64): bilang root, ini-install ang package gamit ang installpkg e-layer-analyzer-...-x86_64-1_ic8tem.txz (o -aarch64-); binubuksan ang programa gamit ang e-layer-analyzer mula sa menu o sa terminal at sa unang pagbukas ay kinokopya nito ang sarili sa ~/E-LAYER-ANALYZER, gaya ng sa .deb.
LI|Fedora at openSUSE: sudo dnf install ./e-layer-analyzer-....x86_64.rpm (o zypper install; mayroon ding .aarch64.rpm at .armv7hl.rpm). Arch, Manjaro, EndeavourOS at Arch Linux ARM: sudo pacman -U e-layer-analyzer-...-x86_64.pkg.tar.zst (o -aarch64). Sa mga package na ito rin, sa unang pagbukas ay kinokopya ng programa ang sarili sa ~/E-LAYER-ANALYZER.
LI|AppImage (x86_64 at aarch64): iisang file para sa halos lahat ng distribusyon ng Linux; ginagawa itong executable at pinapatakbo. Sa unang pagbukas, kinokopya nito ang programa sa ~/E-LAYER-ANALYZER at doon ito pinapatakbo.
LI|Alpine Linux at iba pang Linux na may musl: archive na -alpine-x64- o -alpine-arm64-portatile.tar.gz; kailangan ang mga package na icu-libs at fontconfig (apk add icu-libs fontconfig).
LI|FreeBSD amd64: eksperimental at hindi pa nasusuring package (-freebsd-amd64-sperimentale.tar.gz). Kailangan ang .NET 8 ng komunidad (pkg install dotnet) at ang mga library na SkiaSharp at HarfBuzzSharp na kinompile para sa FreeBSD, na hindi ibinibigay ng Avalonia: kung wala ang mga ito, hindi tatakbo ang programa. Nasa file na LEGGIMI-FREEBSD.txt ang mga tagubilin.
LI|Mac: buksan ang file na .dmg (arm64 para sa Apple Silicon M1-M4, x64 para sa Intel) at, sa pag-right-click sa "Installa E-LAYER-ANALYZER.command", piliin ang Open (Buksan); bilang alternatibo, ang file na -app.zip ay naglalaman lamang ng application.
LI|Lahat ng data ng programa ay nasa folder na data katabi ng programa: mga setting (config.ini), database ng CALL3, mga coefficient ng magnetic field, mga log, na-download na data ng NOAA, mga nakolektang spot. Walang isinusulat sa AppData o sa iba pang folder ng sistema.
LI|Para ilipat ang programa sa ibang computer, kopyahin lamang ang folder nito; para bumalik sa mga unang setting, burahin lamang ang data/config.ini.
LI|Sa folder na data, iniimbak din ng programa ang: lingue (ang mga salin), spot (ang mga nakolektang spot), spot_ms (ang mga spot ng meteor scatter ng YA-MS), swpc (ang datos ng NOAA), mappa (mga baybayin at hangganan mula sa Natural Earth, dina-download mula sa GitHub sa unang pagbukas: sa unang pagkakataon kailangan ng network) at aggiornamento (ang mga package ng awtomatikong update, na maaaring burahin).
LI|Hindi kailanman sine-save ang password ng LoTW; ang username lamang ang maaaring tandaan.
LI|Mga update: mula sa bersiyon 0.4.5, kusang tinitingnan ng programa, sa pagbukas at pagkatapos ay bawat 30 minuto (hanggang 0.4.17 bawat 6 na oras), kung may lumabas na bagong bersiyon sa GitHub. Kung mayroon, ipinapaalam ito sa pamamagitan ng isang window at ng kulay-kahel na ▲ sa bar sa itaas: dina-download ng "I-update ngayon" ang package na angkop sa computer (Windows 64 o 32 bit, Linux, Raspberry Pi, Mac), isinasara ang programa, pinapalitan ang mga file at muli itong binubuksan; ipinagpapaliban ito ng "Mamaya", at hindi na ito iminumungkahi ng "Laktawan ang bersiyong ito". Pinananatili ang mga setting, nakolektang spot at call3.txt. Maaaring patayin ang pagsusuri gamit ang checkbox sa parehong window.
LI|Mula sa bersyon 0.4.12, awtomatiko at tahimik ang mga update: kapag may bagong bersyon sa GitHub, dina-download ito ng programa, ini-install, at kusang nagre-restart nang walang tinatanong. Ang mga nawawalang file ay muling dina-download din nang hindi nagtatanong. Lumalabas lang ang window ng update kapag kinlik ang bersyon sa itaas, o kung papatayin ang awtomatikong update sa MGA SETTING (Pangkalahatan).
LI|Ang awtomatikong update ay para sa installer at zip ng Windows, sa app ng Mac, sa mga archive na .tar.gz at sa AppImage. Sa mga package ng sistema (.deb, .rpm, Arch at Slackware) hindi kusang nag-a-update ang programa: ipinapaalam nito ang bagong bersiyon, na ini-install sa pamamagitan ng pag-download ng bagong package mula sa pahina ng mga Release at pag-install nito gaya ng una.
LI|Kusang nag-a-update din ang modelo ng magnetic field: sa pagbukas at bawat 30 araw, hinahanap ng programa, nang hindi nagtatanong, ang bagong henerasyon ng IGRF sa site ng NOAA at, kung mayroon, dina-download ito sa folder na data at agad na ginagamit.
LI|Mga nawawalang file: sa pagbukas, tinitingnan ng programa kung nasa kaniya ang lahat ng file na kasama nang ipamahagi ito (mga salin, dokumento, talahanayan). Kung may nawawala, inililista ang mga ito ng isang window at kinukuha muli ng button na "I-download mula sa GitHub" mula sa parehong bersiyong inilathala sa GitHub.
LI|Habang nag-a-update, ipinapakita ng window ang progreso ng pag-download at pag-extract. Kung hindi masulatan ang folder ng programa, halimbawa sa loob ng isang system folder, sinasabi ito ng programa at iminumungkahi ang pahina ng release, kung saan dina-download ang package ng installation; kung may pumalya, lumalabas ang dahilan at nagiging "Pahina ng Release" ang button.
H2|1.3 Ang bar sa itaas
P|Sa kaliwang itaas inilalagay ang sariling callsign, ang locator (4, 6 o 8 character) at ang taas ng antenna sa metro; kinukumpirma ito ng button na Ilapat at nag-a-update ang lahat ng tab. Sa kanang itaas makikita ang oras sa UTC, ang pagpili ng color scheme (lahat ng scheme ng YAEC: Maliwanag, Gabi, Itim, walong pastel at Bakas ng meteor; mula sa bersiyon 0.5.0, pati ang anim na tema ng IP-TRX-CTRL: Maliwanag, Gabi at Itim ng IP-TRX-CTRL, Asul, Lila at Berde, ang huling tatlo ay nasa YAEC din) at ang pagpili ng wika (36 wika). Kapag pinalitan ang color scheme o wika, agad na binubuo muli ang window nang hindi nawawala ang nakolektang data.
P|Sa tabi ng oras sa UTC, sinasabi ng nakasulat na NTP:OK (berde) o NTP:FAILED (pula) kung tama ang oras: bawat 5 minuto, tinatanong ng programa ang dalawang time server mula sa sampung nakakalat sa buong mundo at lumilipat sa iba kung hindi sila sumasagot. Ipinapakita ng tooltip ang mga server na ginamit at ang paglihis ng orasan ng PC.
P|Laging ginagamit ng programa ang tamang oras: inilalapat sa sarili nitong orasan ang nasukat na pagkakaiba. Kung lampas sa isang segundo ang pagkakaiba, sa Windows at may karapatang administrator, itinatama rin ng programa ang orasan ng PC, at sinasabi ito ng tooltip ("Naitama na ang orasan ng PC."); sa Linux at Mac, hindi ginagalaw ang orasan ng sistema.
P|Sa tabi ng nakasulat na NTP ay ang ginagamit na bersiyon (halimbawa v0.4.5, kulay-abo): isang click ang agad na tumitingin kung may mas bagong bersiyon sa GitHub. Kapag may lumabas na bagong bersiyon, nagiging kulay-kahel ang nakasulat, halimbawa ▲ 0.4.6, at binubuksan ng isang click ang window ng update.
P|Sa kanan ng tab bar ay ang menu ng kontinente (Europa, Hilagang Amerika, Timog Amerika, Aprika, Asya, Oseanya): inililipat nito ang mga mapang Mercator at ang mga mapa ng F.A.I. at ng aurora sa napiling kontinente at pinipili ang datos ng pagtataya ng kontinenteng iyon (inilalathala lamang ang E-skip ni N0NBH para sa Europa at Hilagang Amerika).
P|Maitatakda rin ang callsign, locator, taas, wika, kulay, kontinente at mga update sa tab na MGA SETTING (kabanata 10), kung saan naroon din ang laki ng titik ng buong programa.
H2|1.4 Ang status bar
P|Sa ibaba, ipinapakita ng status bar kung ilang callsign ang nasa database ng CALL3, ilang spot ang nasa memorya at ang magnetic model na ginagamit (IGRF-14 kasama ang epoch nito). Binubura ang mga spot sa memorya tuwing isinasara ang programa: nagsisimula ang bawat sesyon nang walang lumang spot.
H2|1.5 Ang mga mapa
P|Pare-pareho ang paggamit ng lahat ng mapa: pinalalaki o pinaliliit ng scroll wheel ng mouse, inililipat ang tanaw sa pag-drag gamit ang kaliwang button, at pumipili ang left click ng punto, spot o landas depende sa tab. Sa kanang itaas lumilitaw ang mga coordinate at ang 6-character na locator sa ilalim ng cursor; sa mga azimuthal na mapa pati ang distansiya at azimuth mula sa gitna. Kumakapal ang grid ng mga Maidenhead field at grid square habang nag-zo-zoom.
LI|Bawat mapa ay may legend ng mga kulay at simbolong ginagamit nito sa kaliwang ibaba. Sa unang pagguhit, maaaring lumabas nang ilang segundo ang nakasulat na "Ikinakarga ang mapa (Natural Earth)...".
H1|2. Pangongolekta ng data (DATA COLLECTION)
P|May dalawang sub-tab ang tab: Spot, kasama ang mga telnet session, PSKReporter MQTT, WSJT-X UDP, ang mga nakolektang spot at ang archive na CALL3, at Datos ng propagasyon (kabanata 2.5). Nasa tab na MGA SETTING (kabanata 10) ang mga filter ng mga spot.
H2|2.1 Ang tatlong telnet na sesyon
P|Nagbubukas ang tab na DATA COLLECTION ng hanggang tatlong sabay-sabay na telnet na koneksiyon: isang DX cluster na pinili (default ang ON0DXK na may mga VHF filter), ang Reverse Beacon Network (port 7001 para sa FT8, 7000 para sa CW at RTTY) at ang cluster ng DM4X na may mga spot ng PSKReporter (dm4x.ddns.net, port 8500).
LI|Host at Port: address ng cluster. Login: callsign para sa pag-access (kung blangko, ginagamit ang nasa bar sa itaas). Mga command pagkatapos ng login: mga command na ipapadala pagkatapos ng login, hinihiwalay ng semicolon (halimbawa ang mga filter ng banda).
LI|Binubuksan at isinasara ng Kumonekta at Idiskonekta ang sesyon; kusa itong binubuksan muli ng Kumonekta muli pagkatapos maputol; binubuksan ito ng Kumonekta sa pagsisimula pagbukas ng programa.
LI|Ipinapakita ng console ang mga natanggap na linya; sa kahon sa ibaba nito maaaring isulat ang mga command na ipapadala sa cluster (halimbawa sh/dx 20) at kumpirmahin ang mga ito gamit ang Ipadala o ang Enter key.
H2|2.2 Nasaan ang mga filter
P|Bawat spot na natatanggap sa DATA COLLECTION ay dumaraan sa mga filter bago makarating sa mga tab ng bawat mode ng propagasyon: iisa lang ang pangongolekta ng data para sa buong programa. Mula sa bersiyon 0.4.18, ang mga filter at ang lokal na filter ay nasa tab na MGA SETTING, sub-tab na Pamamahagi ng mga spot (kabanata 10.2).
H2|2.3 Paano binabasa ng programa ang mga spot
P|Mula sa bawat linyang "DX de" kinukuha ng programa ang spotter, frequency, DX, komento, oras at, kung mayroon, ang mga locator at ang mode ng propagasyon na nakasulat sa komento sa anyong JN70CN<ES>JO62QM (ang unang locator ay sa spotter, ang pangalawa ay sa DX; tinatanggap din ang mga anyong may <>, > at panaklong).
LI|Hinahanap sa database ng CALL3 ang mga nawawalang locator; ang mga hindi tiyak na locator (wala pang 6 na character) ay pinapalitan ng 6-character na locator mula sa CALL3, kung mayroon.
LI|Hindi ginagamit para sa sporadic-E ang mga spot na may <MS>, <AU>, <AUR>, <TR>, <AS> o <ACS> sa teksto: para ang mga ito sa meteor scatter, aurora, tropo o aircraft scatter.
LI|Gaya ng sa YA-MS, mga spot ng meteor scatter ang mga nasa karaniwang frequency window ng MS (50190-50300, 70100-70400, 144290-144399 kHz) na walang tanda ng ibang propagasyon, at ang mga may mode na MSK144, FSK441, FSK41, PSK2K, JTMS, JT6M o may <MS>. Eksepsiyon ang FT8 at FT4 sa 50 at 70 MHz: kung kilala ang mode, ang mode ang nagpapasya, kaya napupunta sa sporadic-E ang FT8 sa 70.154 MHz kahit nasa window ito ng meteor scatter.
LI|Napupunta sa tab na AURORA ang mga spot na may <AU> o <AUR>, at sa tab na F.A.I. ang mga may FAI.
H2|2.4 Mga nakolektang spot at ang database ng CALL3
P|Inililista ng pahinang Mga nakolektang spot ang pinakahuling mga spot na may filter ayon sa banda at sa pinagmulan; binubuksan ng button na Buksan ang folder ng mga spot ang data/spot. Ipinapakita ng pahinang CALL3 ang database ng callsign -> locator (format ng JTDX/WSJT): maaaring maghanap ng callsign, i-reload ang database o mag-import ng bagong CALL3.TXT file, na papalit sa kasalukuyang ginagamit (nananatili ang luma bilang backup).
LI|Ang mga column ng mga nakolektang spot ay: UTC, Sanggunian (cluster, RBN o PSKReporter), MHz, Banda, DX kasama ang locator nito, Spotter kasama ang locator nito, km, Prop (ang idineklara o nakilalang mode ng propagasyon) at Komento. Nililimitahan ng menu na Lahat ng sanggunian ang talahanayan sa iisang session.
LI|Ipinapakita ng pahinang CALL3 ang file na ginagamit, ang petsa nito, ang header at ang bilang ng mga callsign na naikarga (higit sa isang milyon sa archive na kasama sa distribusyon).
LI|Mula sa bersyon 0.4.16, iisa na lang ang database ng CALL3 para sa buong programa, ang sa Pagkolekta ng data ng YA-MS (tab na METEOR SCATTER), na may parehong mga patakaran ng LIVETROPOVHF: pag-update mula sa MMMonVHF tuwing 12 oras, mano-manong entry, idinagdag na file, pagwawasto mula sa cluster, natutunang locator, G7VRD tuwing 30 minuto at, bilang huling pinagmulan, ang layer ng JTDX (data/grid_data.bin, mga 365,000 callsign: para lamang sa mga callsign na walang 6-character na locator sa ibang pinagmulan, sa loob lamang ng parehong grid square ng natanggap, at hindi kailanman isinusulat sa data/call3.txt); isinusulat ang mga pagwawasto sa data/call3.txt at minsang ini-import ang mga locator ng data/call3_nuovi.txt. Dumarating din sa UDP ang mga spot mula sa WSJT-X, JTDX at MSHV (pinagmulang WSJT-X UDP, port 2237 na ipinapasa sa 2238).
LI|Ang mga filter na ito mula sa YA-MS (CW, pinakamaliit na layo, mga window ng frequency, mga mode na MS, mga banda) ay para lang sa tab na METEOR SCATTER: sila ang nagpapasya kung aling mga spot ang papasok sa koleksiyon nito. Natatanggap ng ibang mga tab ang lahat ng spot at gumagamit sila ng sarili nilang mga filter.
H2|2.5 Datos ng propagasyon
P|Tinitipon ng sub-tab na Datos ng propagasyon ang mga datos na tumutulong upang malaman kung maaaring magbukas ang isang band. Kusa itong nag-a-update nang hindi hihigit sa isang beses bawat oras; dina-download ito agad ng button na I-update ngayon.
LI|N0NBH (hamqsl.com): ang banner ng kondisyon ng VHF at ang datos ng araw (solar flux, mga index na A at K, X-ray, solar wind, Bz, aurora at aurora latitude) kasama ang E-skip ng Europa at Hilagang Amerika (datos ng DXrobot).
LI|Lumalabas ang mga kondisyon ng VHF ni N0NBH gaya ng pagkakalathala sa hamqsl.com: Band Closed (sarado ang banda), 50MHz ES, 70MHz ES at 144MHz ES (sporadic-E sa bandang iyon), High MUF; para sa aurora, High LAT AUR at Mid LAT AUR (aurora sa matataas o katamtamang latitude).
LI|Bz para sa aurora: NOAA SWPC, real-time na solar wind na sinusukat ng satellite sa punto L1 (DSCOVR/ACE), bawat minuto. Ang negatibo at tuloy-tuloy na Bz ay pabor sa aurora.
LI|Aurora: ang Dst index ng Kyoto (mga geomagnetic storm) at, para sa southern hemisphere, ang mga aurora alert ng Australian Bureau of Meteorology, na nangangailangan ng libreng key na isusulat sa kahong BoM API key. Binubuksan ng mga button na AE index (Kyoto) at SuperDARN convection ang dalawang pahina sa browser.
LI|Ganito binabasa ang antas ng Dst: tahimik sa itaas ng -30 nT, mahinang gambala sa pagitan ng -30 at -50 nT, katamtamang storm sa pagitan ng -50 at -100 nT, malakas na storm mula -100 nT pababa. Kapag may key ng BoM, lumalabas din ang K index ng Australia at ang mga kasalukuyang alerto ng pagbabantay sa aurora.
LI|Meteor scatter: ang graph ng aktibidad ng meteor sa araw na ito (datos ng RMOB) ng Make More Miles on VHF; ang mga meteor shower, ang kahusayan at ang live na trapiko ay nasa tab na METEOR SCATTER.
P|Lumalabas ang buod ng mga datos na ito sa kanang itaas ng mga mapa ng SPORADIC-E at F.A.I. (E-skip ng napiling kontinente) at ng AURORA (aurora ni N0NBH at Bz ng NOAA).
H1|3. Sporadic-E (SPORADIC-E)
P|May tatlong sub-tab ang tab na SPORADIC-E: REAL-TIME, ang mga live na spot na inilalarawan sa kabanatang ito; BENCHMARK Es (kabanata 4) at BENCHMARK 50 MHz (kabanata 5).
H2|3.1 Ang mapa
P|Pinipili ng menu na Mapa ang projection. Azimuthal: mapang azimuthal equidistant na nakasentro sa sariling istasyon, na may zoom slider (mula 300 hanggang 20000 km mula sa gitna, pati gamit ang scroll wheel ng mouse). Mercator: ang mapa ng mundo, na may mga button na Europa at Mundo. Sa parehong projection, iginuguhit sa paligid ng istasyon ang mga bilog ng distansiya ng talahanayan ni IK3XTV [3]: 500 km (pinakamababa ng iisang hop), 1500-2000 km (pinakamainam), 2400 km (pinakamataas ng iisang hop), 5000 km (pinakamataas ng dobleng hop) at 6900 km (pinakamataas ng triple hop).
P|Ang talahanayan ng haba ng mga hop sa 50 MHz ay kay Flavio Egano IK3XTV, «Propagazione sui 6 metri - Caratteristiche generali» (Propagasyon sa 6 metro - Mga pangkalahatang katangian) [3]; ang mga ulap na Es ay nasa taas na humigit-kumulang 100 km, at nililimitahan nito ang iisang hop sa mga 2000 km [29]. Sinusunod ng mga singsing sa mga mapa at ng bilang ng hop ang mga distansiyang ito:
TAB|Hop;Pinakamababang distansiya;Pinakamainam na distansiya;Pinakamataas na distansiya
TAB|Iisang hop;500-650 km;1500-2000 km;2200-2400 km
TAB|Dobleng hop;2800-3000 km;3200-4000 km;4400-5000 km
TAB|Triple hop;-;4800-6400 km;6900 km
P|Sa mga azimuthal na tanaw, ipinapakita ng mga putol-putol na bilog ang km mula sa gitna; nagbabago ang pagitan ng mga bilog ayon sa zoom at ipinapakita ng panlabas na gilid ang pinakamalayong distansiyang ipinapakita.
H2|3.2 Ang mga kontrol
LI|Mga banda: 10, 8, 6, 4 at 2 m (hindi sinusuri ang 432 MHz: hindi umiiral ang sporadic-E [22]-[24]); naka-off sa simula ang 8 m (40 MHz). Window ng oras ng mga spot mula 15 minuto hanggang 12 oras.
LI|Taas ng Es (default 110 km) at pinakamababang elebasyon ng mga antenna (default 1°); isinasaalang-alang ng elebasyon ang troposperikong repraksiyon (radius ng Daigdig 4/3), kaya umaabot ang iisang hop sa mga 2440 km.
LI|Unang hop (pantay na hop): ipinapakita ang unang hop ng parehong istasyon; Maikling unang hop sa loob ng…: ipinapakita ang hinuha ng may-akda tungkol sa maikling unang hop (default 1200 km) [4].
LI|Mga ulap ng Es sa mga Maidenhead grid square: kinukulayan ang mga grid square ng mga punto ng repleksiyon ayon sa pinakamataas na frequency ng mga spot (berde hanggang 29 MHz, dilaw hanggang 51, kahel hanggang 71, pula hanggang 145 MHz). Kung umabot ang posibleng MUF ng ulap sa pinakamahabang hop (2400 km) sa mas mataas na band, kumikislap ang grid square sa kulay ng band na iyon. Para sa 144 MHz, umiiral ang patakaran ng may-akda: kumikislap nang pula ang grid square lamang kung nagbibigay ang ulap ng hop sa 50 MHz sa pagitan ng 450 at 500 km (450 km na may tolerance na 50 km).
LI|144 MHz patungong Canary Islands, Madeira at Azores (patakaran ng may-akda): lampas sa 2400 km, balido lamang ang spot kung hindi bababa sa dalawang spot ang tumuturo sa parehong ulap ng Es; iginuguhit ang Es hop, ang ulap at ang putol-putol na bahaging tropo hanggang sa isla. Hindi inilalapat ang patakaran sa 50 at 70 MHz.
H2|3.3 Mga talahanayan at detalye
P|Inililista ng talahanayang Mga spot ng Es ang mga balidong spot kasama ang distansiya, bilang ng hop at pinakamababang foEs; inililista ng talahanayang Mga ulap ng Es (grid square) ang mga grid square na may tinatayang ulap at ang MUF na ibibigay ng mga ito para sa sariling istasyon (pula 144 MHz, kahel 70 MHz, dilaw 50 MHz). Kapag may nakatakdang zoom, ipinapakita lamang ng mga talahanayan ang nakikita sa mapa.
LI|Mga column ng talahanayang Mga spot ng Es: UTC, MHz, DX, Spotter, km, Mga hop, foEs≥ (tinantyang pinakamababang foEs) at Prop. Mga column ng talahanayang Mga ulap ng Es: Grid square, foEs≥, bilang ng mga spot, azimuth at distansya mula sa sariling istasyon, at Aking MUF.
LI|Mga kulay at simbolo sa mapa: berde ang mga landas sa 10 m, dilaw sa 8 m, mapusyaw na asul sa 6 m, lila sa 4 m at kahel sa 2 m; maliit na dilaw na parisukat = gitnang punto ng iisang hop; maliit na kahel na parisukat = unang hop ng spotter at maliit na lilang parisukat = unang hop ng DX (pantay na mga hop); maliit na kahel na bilog = maikling unang hop (hinuha ni IC8TEM); berdeng bilog = abot ng iisang hop mula sa sariling istasyon.

H2|3.4 Ang mga patakaran ng may-akda
LI|144 MHz: nagsisimula ang sporadic-E sa lampas 900 km; hindi iginuguhit ang iisang spot; iginuguhit ito kung sa loob ng 5 minuto ay dumating ang pangalawang spot sa parehong ulap o kung may maikling-hop na spot sa 50 MHz sa paligid. Sinasabi ng berdeng linya sa itaas kung ilang spot ang naghihintay ng kumpirmasyon.
LI|Trans-equatorial: patungo sa kontinental na Africa (kasama ang Madagascar) at South America, kung ang gitnang punto ay nasa sinturon ng magnetic inclination sa pagitan ng -15° at +15°, ang koneksiyon ay trans-equatorial at hindi sporadic-E, maliban kung idineklara ng spot ang <ES>. Hindi saklaw ng patakaran ang Canary Islands, Madeira, Cape Verde at ang Arabian Peninsula. Ang halagang 15° ay kinuha kay Cracknell [66], na naglalagay sa mga sona ng TEP sa mga 5-15° mula sa linya ng zero inclination (pasya ng may-akda).
LI|50 MHz: hindi sporadic-E sa loob ng 450 km. Ang mga spot na FT8 at FT4 ay sporadic-E lamang kung bahagi sila ng isang ulap, ibig sabihin kung sa loob ng 4 na minuto ay may isa pang spot sa 50 MHz na ang gitnang punto ay nasa loob ng 150 km; ang nag-iisang spot na FT8 o FT4 ay napupunta sa meteor scatter (patakaran ng may-akda).
LI|70 MHz: hindi sporadic-E sa loob ng 450 km (patakaran ng may-akda; nakikita ni G0ISW [65] ang pinakamaikling sporadic-E na lampas sa 400 km sa 50 at 70 MHz). Ang FT8 at FT4 ay napupunta sa sporadic-E kahit nasa loob ng window ng meteor scatter ng bandplan.
LI|40 MHz (8 m): kinukuha ang pinakamaikling distansiya mula sa 450 km ng 50 MHz gamit ang secant law (mga 330 km) at ang mga distansiya lamang na nasa loob ng unang hop ng heometriya ng E layer ang tinatanggap (mga 2440 km).
LI|144 MHz: ang mga spot na Q65 at JT65 ay EME at hindi pumapasok sa sporadic-E, maliban kung may <ES> sa teksto. Nakikita ni G0ISW [65] ang sporadic-E sa 144 MHz lampas lamang sa 1400 km: nagsisimula sa 900 km ang patakaran ng may-akda pero humihingi ito ng kumpirmasyon.

H1|6. F.A.I.
H2|6.1 Ang dalawang tanaw
P|Pinag-aaralan ng tab na F.A.I. ang scatter mula sa mga iregularidad na nakahanay sa magnetic field (pangunahing sanggunian [1], [2]). Idinagdag ang babalang «walang karaniwang zone», itinampok ang kahon ng anggulong β (ang pagpiling pinakamabigat), iisang petsa ng pagkalkula, ang «Manwal ng paggamit» at ang paghahambing sa 181 767 tunay na spot sa 50 MHz mula sa HamSCI Meteor Scatter QSO Party noong Agosto 2025: maaasahan ang mga oras at ang mga panig ng daanan, pahiwatig lamang ang mga porsiyento.

H1|8. AURORA
P|Ginagamit ng tab na AURORA ang parehong mga tanaw ng F.A.I. (default na taas 110 km, Lange-Hesse [12]) kasama ang data ng space weather ng NOAA [15]: ang OVATION auroral oval (malabong kulay sa mapa), ang Kp index ng huling tatlong araw at ang solar wind, na dina-download tuwing 5 minuto sa data/swpc o kaagad gamit ang I-download ang NOAA ngayon. Nagmumungkahi ang programa ng direksiyon ng antenna para sa parehong istasyon.
LI|Mga sariling kontrol ng tab: ang kahong Auroral oval (NOAA OVATION), naka-on sa simula, ay nagpapakita ng malabong oval sa mapa at ginagamit ito bilang timbang sa pagpili ng scatter point; agad na ina-update ng I-download ang NOAA ngayon ang datos. Ipinapakita ng kahong Space weather (NOAA SWPC) ang graph ng planetary Kp ng huling 3 araw, bawat 3 oras, at ang oras ng oval at ng huling pag-download. Ginagamit ang mga view na Scatter trail at Iso-repleksiyon gaya sa F.A.I. (kabanata 6), na may tolerance na 3°.
LI|Iginuguhit sa mapa ang mga spot ng aurora sa panahong pinili sa mga filter ng MGA SETTING (default ang huling 2 oras, hanggang 30) kasama ang kinalkulang scatter point (kahel na bilog) kung nakabukas ang checkbox na Mga spot na <AU>/<AUR> sa mapa na may kalkulasyon; lumalabas sa mga resulta ang QTF at elebasyon ng dalawang istasyon.
LI|Sa mga resulta ng view na Scatter trail, lumalabas ang probabilidad ng aurora sa scatter point (malabo kapag Kp ≤ 2; sa iba pa ayon sa NOAA oval), ang karaniwang QTF sa pagitan ng N at NE (S-SE sa southern hemisphere) kasama ang paglihis mula sa direktang landas, at mga payo tungkol sa Doppler at sa mga mode (CW/SSB o Q65 na may malapad na submode: madalas hindi nakaka-decode ang FT8). Mas pinipiling hanapin ang scatter point sa loob ng saklaw ni Lange-Hesse ng bawat istasyon, na may perpendicularity sa loob ng ±3°: 370-1100 km sa 54° geomagnetic latitude, mas malapit para sa mga istasyong mas nasa timog at mas malayo para sa mga mas nasa hilaga, ayon sa IGRF-14 inclination (halimbawa Capri mga 260-990 km, Oslo 470-1200 km). Ibinibigay ng mga resulta ang saklaw ng bawat istasyon; kung nasa labas ang iminungkahing punto, minamarkahan ito ng programa.
LI|Ang probabilidad ng aurora sa scatter point ay pinagpapasyahan sa ganitong pagkakasunod: malabo kapag Kp ≤ 2, maliban kung may storm (Dst ≤ -50 nT); sa southern hemisphere, malamang kapag may alerto ng aurora mula sa BoM; malamang kapag Dst ≤ -100 nT at posible kapag Dst ≤ -50 nT, kung hindi zero ang oval sa punto; malamang kapag ang oval ay mula 10%; posible kapag ang oval ay mula 3% o kapag Kp ≥ 5; kung hindi, malabo.
LI|Minamarkahang kaduda-duda ang mga spot ng aurora na lampas sa 2000 km: ayon kay Newton [48], umaabot ang aurora sa mga 1000 km hilaga-timog at 2000 km silangan-kanluran. Iginuguhit nang berde sa direktang landas ang mga spot ng aurora-E (AUE, AU-E, AURORAL E): ito ay sporadic-E na nagmula sa aurora, walang Doppler.
LI|Ibinibigay ng mga resulta ang solar na oras sa scatter point: sa loob ng 4 na oras mula sa lokal na hatinggabi nangyayari ang karamihan ng mga repleksiyon ng aurora (Reeve [52]). Sa southern hemisphere, umaabot ang aurora sa 50 MHz hanggang mga 2000 km sa mga landas na silangan-kanluran (ANVDG [55]); nagbibigay ang aurora-E ng mas mahina at mas matatag na signal sa direktang landas (SM2CEW-SM0FOB [54]).
LI|Bukod sa pinakamalamang na scatter point, ibinibigay ng mga resulta ang saklaw ng QTF ng dalawang istasyon sa buong bakas (paglihis ≤ 1.5°): maaaring manggaling ang aurora sa anumang punto ng saklaw, at mas pinapaboran ng pinakamalamang na punto ang pinakamaikling landas.

LI|Sa itaas ng mapa ay may mga tab ng banda: 28, 50, 70, 144 at 432 MHz palagi, at ang iba pang bandang nasa log, bawat isa kasama ang bilang ng mga grid square na nakontak at nakumpirma. Nililimitahan ng menu na Propagasyon ang mga grid square sa iisang mode: ES, FAI, aurora (AUR/AUE), MS, TR, EME, F2 o ang mga QSO na walang PROP_MODE.
LI|Mga kulay: kahel = nakontak at hindi pa nakumpirma, asul = nakumpirma sa QSL, berde = nakumpirma sa LoTW. Ibinibigay ng talahanayang Mga grid square ng banda ang Grid square, QSO, Katayuan, Mga callsign at Prop; ang pag-click sa isang grid square sa mapa o sa talahanayan ay nagpapakita ng mga detalye nito sa kahong Napiling grid square.
LI|Humihingi ang I-download mula sa LoTW… ng username, password at, kung gusto, iisang callsign; dina-download nito ang lahat ng QSO na na-upload sa LoTW kasama ang mga detalye ng kumpirmasyon. Kung tinanggihan ng LoTW ang pag-access, sinasabi ito ng programa; iniimbak ng kahong Tandaan ang username ang username, hindi kailanman ang password.
H1|10. MGA SETTING
P|Tinitipon ng tab na MGA SETTING ang mga pangkalahatang opsiyon ng programa at ang pamamahagi ng mga spot sa mga tab. May dalawa itong sub-tab: Pangkalahatan at Pamamahagi ng mga spot.
H2|10.1 Pangkalahatan
LI|Istasyon: callsign, locator at taas, ang mga ito rin sa hanay sa itaas; kinukumpirma ang mga ito ng Ilapat para sa lahat ng tab.
LI|Hitsura: wika, kulay at laki ng titik ng buong programa, mula 85 hanggang 140 %, gaya ng sa YA-MS. Muling binubuo ng wika at kulay ang window nang hindi nawawala ang mga setting at ang mga spot.
LI|Mga mapa at datos ng pagtataya: ang kontinente, ang parehong menu ng bar ng mga tab.
LI|Oras: ang kalagayan ng pagsusuri ng NTP at ang pagkakaiba ng oras ng mga server at ng oras ng PC.
LI|Mga update: ang pagsusuri sa GitHub sa pagbukas at bawat 30 minuto, ang awtomatiko at tahimik na update (hindi para sa mga package ng sistema na .deb, .rpm, Arch at Slackware) at ang button na Suriin ngayon.
LI|Datos: ang button na nagbubukas ng folder na data. Nananatili ang API key ng Bureau of Meteorology sa DATA COLLECTION, Datos ng propagasyon.
H2|10.2 Pamamahagi ng mga spot
P|Sa kaliwa, inililista ng isang talahanayan ang mga patakarang ginagamit ng programa para pagpasyahan kung saan pupunta ang bawat spot, ayon sa pagkakasunod ng paglalapat sa mga ito: ang unang patakarang tumutugma ang nagpapasya ng tab. Ang mga halagang ipinapakita ay ang mga nakatakda sa mga filter. Sa kanan ang lokal na filter at ang mga filter ng bawat mode, sa limang sub-tab.
P|Sa itaas ang kahon ng lokal na filter, naka-on sa simula: itinatapon ang mga linyang "DX de" na may frequency na mas mababa sa 27990.0 kHz o mas mataas sa 145 MHz, hindi lumalabas sa console at hindi iniimbak; sa pagitan ng 430 at 440 MHz, mga spot ng aurora lamang ang pinapadaan. Kapaki-pakinabang ito lalo na sa RBN at PSKReporter, na nagpapadala ng napakaraming spot sa HF. Kapag pinatay ang kahon, dumaraan ang lahat. Sa ilalim ay may limang sub-tab.
LI|Meteor scatter: ang filter ng YA-MS (mga frequency window na karaniwan sa MS, mga tag ng ibang propagasyon, mga digital mode ng MS at <MS>, mga banda, pagsubok ng filter at mga counter). Sa loob ng E-LAYER ANALYZER, itinatakda ang filter ng YA-MS sa tab na METEOR SCATTER at para lamang sa tab na iyon.
LI|Sporadic-E: ang mga tag sa pagitan ng < > na nag-aalis ng isang spot sa sporadic-E; ang mga patakaran sa 28, 40, 50 at 70 MHz (sa 50 at 70 MHz, hindi sporadic-E sa loob ng 450 km; sa 40 MHz mula mga 330 km hanggang sa unang hop, mga 2440 km; ang FT8 at FT4 sa 50 MHz ay sporadic-E lamang kung bahagi sila ng isang ulap; sa 28 MHz, kinukuha ang pinakamaikling distansiya mula sa distansiya ng 50 MHz ayon kay IK3XTV, mga 170 km; hindi eksklusibong batayan ang bandplan, kaya nananatili sa sporadic-E ang spot na nasa window ng meteor scatter maliban kung digital mode na MS o <MS>); ang patakaran sa 144 MHz (minimum na distansya; kumpirmasyon ng pangalawang spot sa parehong ulap sa loob ng ilang minuto, o ng maikling-hop na spot sa 50 MHz sa paligid) at ang patakarang trans-equatorial kasama ang sinturon nito ng magnetic inclination, na umiiral para sa Africa at Timog Amerika (patakaran ng may-akda) at, sa buong mundo, para sa mga koneksiyong 3000-8000 km na tumatawid sa magnetic equator sa halos hilaga-timog na direksiyon (Kennewell at Wilkinson [49]). Ibinabalik ng button na Ibalik ang mga patakaran ng may-akda ang mga default na halaga.
LI|Mga unang halaga ng mga tuntunin ng sporadic-E, lahat ay mababago: pinakamaikling distansya sa 50 at 70 MHz 450 km; FT8 at FT4 sa 50 MHz na may isa pang spot sa loob ng 4 na minuto at gitnang punto sa loob ng 150 km; naka-on ang tuntunin ng 144 MHz, na may pinakamaikling distansya na 900 km at kumpirmasyon sa loob ng 5 minuto mula sa ikalawang spot sa isang ulap sa loob ng 300 km, o mula sa isang spot sa 50 MHz ng huling 15 minuto na may maikling hop hanggang 1200 km; naka-on ang tuntuning trans-equatorial, na may saklaw ng magnetic inclination na ±15°.
LI|F.A.I.: ang mga salitang nagpapahiwatig ng spot ng F.A.I. (default FAI: tinatanggap ang <FAI> o fai, sa malalaki, maliliit o halong titik; hindi pumapasok sa sporadic-E ang mga spot na ito), ang mga banda (6, 4 at 2 m: hindi umaabot sa 432 MHz ang F.A.I.) at ang panahon ng mga spot sa mapa (default 24 oras).
LI|Aurora: ang mga salita ng mga spot ng aurora, may < > man o wala at malaki man o maliit ang titik (default AU at AUR), ang mga banda at ang panahon ng mga spot sa mapa (default 2 oras).
LI|Pagsubok ng mga filter: isinusulat o idinidikit ang isang linya ng cluster at ipinapakita ng programa kung paano ito inuuri ng mga filter (meteor scatter, aurora, F.A.I., trans-equatorial, sporadic-E), kasama ang banda, locator at distansya.
H1|11. Mga dokumento
P|Inililista ng tab na MGA SANGGUNIAN ang mga sangguniang binanggit ng programa, bawat tab. Inilalahad ng tab na BUOD NG MGA PAGPILI SA KALKULASYON ang mga pormula at mga pagpili sa kalkulasyon kasama ang mga sanggunian sa bawat hakbang; ipinapaliwanag ng MANWAL NG PAGGAMIT na ito kung paano gamitin ang programa; inilalahad ng TEKNIKAL NA ULAT ang mga dahilang gumabay sa pagbuo ng programa. Maaaring i-export sa Word ang tatlong dokumento.
LI|May mga button sa itaas ng bawat dokumento: I-export sa Word (.docx)..., na nagse-save ng kopya nito kung saan mo gusto, at Buksan sa Word, na nagbubukas nito sa default na programa para sa mga file na .docx. Sinusunod ng mga dokumento ang wikang pinili sa itaas.
H1|12. Mga praktikal na payo
LI|Una sa lahat, isulat ang callsign at locator sa itaas at pindutin ang Ilapat: doon nagmumula ang lahat ng distansiya, MUF at elebasyon.
LI|Sa RBN at PSKReporter, panatilihing nakabukas ang lokal na filter, para hindi mapuno ang memorya ng mga spot sa HF.
LI|Para suriin ang isang nakaraang season, gamitin ang dalawang BENCHMARK kasama ang sariling log; para sa aurora at F.A.I., laging suriin ang iminungkahing punto gamit ang tanaw na Iso-repleksiyon.
LI|Indikatibo lamang ang mga kalkulasyon: sinasabi ng isang spot o QSO na bukas ang landas, hindi kung saan eksaktong naroon ang ulap.
H1|13. Mga karaniwang problema
LI|NTP:FAILED: walang time server na sumagot. Kadalasan, hinaharangan ng firewall ang port na UDP 123; nagpapatuloy ang programa gamit ang orasan ng PC at muling sumusubok bawat 5 minuto.
LI|Hindi kumokonekta o agad nagsasara ang telnet session: suriin ang host, port at login (maraming cluster ang humihingi ng callsign), at tiyaking walang ibang session na bukas na gamit ang parehong callsign, halimbawa mula sa ibang programa.
LI|Walang spot sa SPORADIC-E: suriin ang mga napiling banda at window ng oras, na hindi itinatapon ng lokal na filter ang banda (pinapadaan nito mula 27990 kHz hanggang 145 MHz, at sa pagitan ng 430 at 440 MHz aurora lamang) at, sa 144 MHz, na may kumpirmasyon ang spot (kabanata 3.4). Sinasabi ng Subok ng mga filter (MGA SETTING, Pamamahagi ng mga spot) kung paano inuuri ang isang linya ng cluster.
LI|Walang laman ang mga mapa sa unang pagbukas: dina-download mula sa GitHub ang mga baybayin at hangganan sa unang pagkakataon; kailangan ng network, at pagkatapos ay nananatili ang mga ito sa data/mappa.
LI|Tinatanggihan ng LoTW ang pag-access: suriin ang username at password sa site ng LoTW; sa malalaking log, maaaring tumagal nang ilang minuto ang pag-download.
LI|Hindi nagsisimula o pumapalya ang awtomatikong update: suriin ang network at na nasusulatan ang folder ng programa; sa mga package na .deb, .rpm, Arch at Slackware, sadyang hindi ito nagsisimula. Sa anumang kaso, mula sa pahina ng release ay maaaring i-install nang mano-mano ang bagong bersiyon sa ibabaw ng luma, nang hindi nawawala ang folder na data.
