TITLE|E-LAYER ANALYZER user manual
SUB|In-depth user manual - by Costantino IC8TEM - version 0.5.0, November 2026. Numbers in square brackets refer to the SOURCES tab; the formulas and calculation choices are in the SUMMARY OF THE CALCULATION CHOICES tab.
H1|1. Before you start
H2|1.1 What the program does
P|E-LAYER ANALYZER brings together in a single program the tools for studying the VHF propagation modes that pass through the E layer of the ionosphere: sporadic-E, including multi-hop and extra-continental, F.A.I. (field-aligned irregularities), meteor scatter, with the integrated YA-MS program, and radio aurora. It works on DX cluster spots in real time and on ADIF logs, and shows every result on a map that takes up two thirds of the window, with the data and calculations in the right-hand third.
H2|1.2 Installation and data folder
P|The program runs on Windows (64 bit, 32 bit and ARM64), Linux (x86_64, ARM64, armv7l and Alpine), Raspberry Pi (Raspberry Pi OS 64 and 32 bit, Slackware ARM64) and Mac (Apple Silicon and Intel); for FreeBSD amd64 there is an experimental package. It is downloaded from the Releases page of the GitHub repository: for Windows there is an installer and a portable version in a .zip file; for Linux the .deb, .rpm, Arch and Slackware packages, the AppImage and the .tar.gz archives with the installation script; for Mac a .dmg image. There are no versions for Linux i686 (32-bit PCs) and OpenBSD, because .NET does not exist for those systems.
LI|Windows: the installer puts the program in C:\E-LAYER-ANALYZER, with the data folder next to it; the portable version is extracted to any folder and started with E-LAYER-ANALYZER.exe. For PCs with an ARM processor (Snapdragon) there are the -win-arm64- files.
LI|Linux and Raspberry Pi: with the .deb package (sudo apt install ./e-layer-analyzer_..._amd64.deb, or _arm64.deb for 64-bit Raspberry Pi OS and _armhf.deb for the 32-bit one) the program starts from the menu and on its first start copies itself to ~/E-LAYER-ANALYZER; with the .tar.gz archive (linux-x64, linux-arm64, linux-arm or linux-armv7l) you extract it and start ./E-LAYER-ANALYZER, or ./installa.sh installs it in ~/E-LAYER-ANALYZER with the icon in the menu.
LI|Slackware (x86_64 and ARM64): as root, install the package with installpkg e-layer-analyzer-...-x86_64-1_ic8tem.txz (or -aarch64-); the program starts with e-layer-analyzer from the menu or the terminal and on its first start copies itself to ~/E-LAYER-ANALYZER, as with the .deb.
LI|Fedora and openSUSE: sudo dnf install ./e-layer-analyzer-....x86_64.rpm (or zypper install; there are also .aarch64.rpm and .armv7hl.rpm). Arch, Manjaro, EndeavourOS and Arch Linux ARM: sudo pacman -U e-layer-analyzer-...-x86_64.pkg.tar.zst (or -aarch64). With these packages too the program copies itself to ~/E-LAYER-ANALYZER on its first start.
LI|AppImage (x86_64 and aarch64): a single file for almost all Linux distributions; make it executable and start it. On its first start it copies the program to ~/E-LAYER-ANALYZER and starts it from there.
LI|Alpine Linux and other Linux systems with musl: archive -alpine-x64- or -alpine-arm64-portatile.tar.gz; the icu-libs and fontconfig packages are needed (apk add icu-libs fontconfig).
LI|FreeBSD amd64: experimental, unverified package (-freebsd-amd64-sperimentale.tar.gz). It needs the community .NET 8 (pkg install dotnet) and the SkiaSharp and HarfBuzzSharp libraries compiled for FreeBSD, which Avalonia does not provide: without them the program does not start. The instructions are in the file LEGGIMI-FREEBSD.txt.
LI|Mac: open the .dmg file (arm64 for Apple Silicon M1-M4, x64 for Intel), right-click "Installa E-LAYER-ANALYZER.command" and choose Open; alternatively the -app.zip file contains just the application.
LI|All the program's data are kept in the data folder next to the program: settings (config.ini), CALL3 database, magnetic field coefficients, logs, downloaded NOAA data, collected spots. Nothing is written to AppData or to other system folders.
LI|To move the program to another computer just copy its folder; to return to the initial settings just delete data/config.ini.
LI|In the data folder the program also keeps: lingue (the translations), spot (the collected spots), spot_ms (the YA-MS meteor scatter spots), swpc (the NOAA data), mappa (Natural Earth coastlines and borders, downloaded from GitHub at the first start: the first time a network connection is needed) and aggiornamento (the automatic update packages, which can be deleted).
LI|The LoTW password is never saved; only the user name can be remembered.
LI|Updates: from version 0.4.5 the program checks by itself, at start-up and then every 30 minutes (every 6 hours up to 0.4.17), whether a new version has been released on GitHub. If so, it reports it with a window and with the orange ▲ label in the top bar: "Update now" downloads the package suited to the computer (Windows 64 or 32 bit, Linux, Raspberry Pi, Mac), closes the program, replaces the files and restarts it; "Later" postpones, "Skip this version" stops proposing it. Settings, collected spots and call3.txt are kept. The check can be switched off with the box in the same window.
LI|From version 0.4.12 updates are automatic and silent: when a new version is on GitHub the program downloads it, installs it and restarts by itself without asking anything. Missing files are also downloaded again without asking. The update window appears only with a click on the version at the top, or if automatic update is switched off in SETTINGS (General).
LI|Automatic update applies to the Windows installer and zip, the Mac app, the .tar.gz archives and the AppImage. With the system packages (.deb, .rpm, Arch and Slackware) the program does not update itself: it reports the new version, which is installed by downloading the new package from the Releases page and installing it like the first one.
LI|The magnetic field model also updates itself: at start-up and every 30 days the program looks, without asking, for the new IGRF generation on the NOAA website and, if there is one, downloads it into the data folder and uses it at once.
LI|Missing files: at start-up the program checks that it has all the files it was distributed with (translations, documents, tables). If any is missing, a window lists them and the "Download from GitHub" button fetches them again from the same version published on GitHub.
LI|During the update the window shows the progress of the download and of the extraction. If the program folder is not writable, for example inside a system folder, the program says so and offers the release page, from which the installation package can be downloaded; if something fails the reason is shown and the button becomes "Release page".
H2|1.3 The top bar
P|At the top left you enter your callsign, your locator (4, 6 or 8 characters) and the antenna height in metres; the Apply button confirms them and all the tabs are updated. At the top right are the UTC time, the choice of colour scheme (all the YAEC schemes: Light, Night, Black, eight pastels and Meteor trail; from version 0.5.0 also the six themes of IP-TRX-CTRL: Light, Night and Black of IP-TRX-CTRL, Blue, Purple and Green, the last three also present in YAEC) and the choice of language (36 languages). When the colour scheme or the language is changed the window is rebuilt at once, without losing the data collected.
P|Next to the UTC time, NTP:OK (green) or NTP:FAILED (red) tells whether the time is aligned: every 5 minutes the program queries two time servers out of ten spread around the world and moves on to others if they do not answer. The tooltip shows the servers used and the offset of the PC clock.
P|The program always uses the correct time: the measured offset is applied to its own clock. If the offset exceeds one second, on Windows and with administrator rights the program also corrects the PC clock, and the tooltip says so ("The PC clock has been corrected"); on Linux and Mac the system clock is not touched.
P|Next to the NTP label is the version in use (for example v0.4.5, in grey): a click checks at once whether a newer one is available on GitHub. When a new version is out the label turns orange, for example ▲ 0.4.6, and a click opens the update window.
P|On the right of the tab bar is the continent menu (Europe, North America, South America, Africa, Asia, Oceania): it moves the Mercator maps and the F.A.I. and aurora maps to the chosen continent and selects the forecast data for that continent (N0NBH's E-skip is published only for Europe and North America).
P|Callsign, locator, height, language, colour scheme, continent and updates can also be set in the SETTINGS tab (chapter 10), which also has the font size of the whole program.
H2|1.4 The status bar
P|At the bottom, the status bar shows how many callsigns the CALL3 database contains, how many spots are in memory and the magnetic model in use (IGRF-14 with its epoch). The spots in memory are cleared every time the program is closed: each session starts again without old spots.
H2|1.5 The maps
P|All the maps are used in the same way: the mouse wheel zooms in or out, dragging with the left button moves the view, and a left click selects a point, a spot or a path depending on the tab. At the top right the coordinates and the 6-character locator under the cursor are shown; on the azimuthal maps also the distance and the azimuth from the centre. The grid of Maidenhead fields and squares becomes denser as you zoom in.
LI|Each map has at the bottom left the legend of the colours and symbols it uses. When a map is first drawn the text "Loading the map (Natural Earth)..." may appear for a few seconds.
H1|2. Data collection (DATA COLLECTION)
P|The tab has two sub-tabs: Spots, with the telnet sessions, PSKReporter MQTT, WSJT-X UDP, the collected spots and the CALL3 database, and Propagation data (section 2.5). The spot filters are in the SETTINGS tab (chapter 10).
H2|2.1 The three telnet sessions
P|The DATA COLLECTION tab opens up to three simultaneous telnet connections: a DX cluster of your choice (by default ON0DXK with the VHF filters), the Reverse Beacon Network (port 7001 for FT8, 7000 for CW and RTTY) and the DM4X cluster with the PSKReporter spots (dm4x.ddns.net, port 8500).
LI|Host and Port: address of the cluster. Login: callsign used to log in (if empty, the one in the top bar is used). Commands after login: commands to be sent after login, separated by semicolons (for example the band filters).
LI|Connect and Disconnect open and close the session; Reconnect reopens it automatically after a drop; Connect at startup opens it when the program starts.
LI|The console shows the lines received; in the box below you can type commands to send to the cluster (for example sh/dx 20) and confirm them with Send or with the Enter key.
H2|2.2 Where the filters are
P|Every spot received in DATA COLLECTION passes through the filters before reaching the tabs of each propagation mode: there is only one data collection for the whole program. From version 0.4.18 the filters and the local filter are in the SETTINGS tab, Spot routing sub-tab (section 10.2).
H2|2.3 How the program reads the spots
P|From each "DX de" line the program extracts spotter, frequency, DX, comment, time and, when present, the locators and the propagation mode written in the comment in the form JN70CN<ES>JO62QM (the first locator is the spotter's, the second the DX's; the forms with <>, > and brackets are also accepted).
LI|Missing locators are looked up in the CALL3 database; imprecise locators (fewer than 6 characters) are replaced with the 6-character locator from CALL3, when available.
LI|Spots with <MS>, <AU>, <AUR>, <TR>, <AS> or <ACS> in the text are not used for sporadic-E: they serve meteor scatter, aurora, tropo or aircraft scatter.
LI|As in YA-MS, meteor scatter spots are those in the frequency windows typical of MS (50190-50300, 70100-70400, 144290-144399 kHz) with no mention of another propagation mode, and those with the modes MSK144, FSK441, FSK41, PSK2K, JTMS, JT6M or with <MS>. FT8 and FT4 on 50 and 70 MHz are an exception: if the mode is known the mode decides, so the 70.154 MHz FT8 goes to sporadic-E even though it falls in the meteor scatter window.
LI|Spots with <AU> or <AUR> go to the AURORA tab, those with FAI to the F.A.I. tab.
H2|2.4 Collected spots and CALL3 database
P|The Collected spots page lists the latest spots with a filter by band and by source; the Open the spot folder button opens data/spot. The CALL3 page shows the callsign -> locator database (JTDX/WSJT format): you can search for a callsign, reload the database or import a new CALL3.TXT file, which replaces the one in use (the old one is kept as a backup copy).
LI|The columns of the collected spots are: UTC, Source (cluster, RBN or PSKReporter), MHz, Band, DX with its locator, Spotter with its locator, km, Prop (the declared or recognised propagation mode) and Comment. The All sources menu limits the table to a single session.
LI|The CALL3 page shows the file in use, its date, the header and the number of callsigns loaded (more than a million with the distributed database).
LI|From version 0.4.16 there is a single CALL3 database for the whole program, the one of the YA-MS Data collection (METEOR SCATTER tab), with the same rules as LIVETROPOVHF: update from MMMonVHF every 12 hours, manual entries, added files, cluster corrections, learned locators, G7VRD every 30 minutes and, as the last source, the JTDX layer (data/grid_data.bin, about 365,000 callsigns: it applies only to callsigns without a 6-character locator in the other sources, only in the same square as the one received, and it is never written into data/call3.txt); corrections are written into data/call3.txt and the locators of data/call3_nuovi.txt are imported once. Spots from WSJT-X, JTDX and MSHV also arrive via UDP (source WSJT-X UDP, port 2237 forwarded to 2238).
LI|These filters, which come from YA-MS (CW, minimum distance, frequency windows, MS modes, bands), apply only to the METEOR SCATTER tab: they decide which spots enter its collection. The other tabs receive all spots and use their own filters.
H2|2.5 Propagation data
P|The Propagation data sub-tab gathers the data that help to understand whether a band may open. They update by themselves at most once an hour; the Update now button downloads them at once.
LI|N0NBH (hamqsl.com): the VHF conditions banner and the solar data (solar flux, A and K indices, X-rays, solar wind, Bz, aurora and auroral latitude) with the E-skip for Europe and North America (DXrobot data).
LI|The N0NBH VHF conditions appear as hamqsl.com publishes them: Band Closed (band closed), 50MHz ES, 70MHz ES and 144MHz ES (sporadic-E on that band), High MUF; for aurora High LAT AUR and Mid LAT AUR (aurora at high or mid latitudes).
LI|Bz for aurora: NOAA SWPC, real-time solar wind measured by the satellite at the L1 point (DSCOVR/ACE), every minute. A negative and persistent Bz favours aurora.
LI|Aurora: the Kyoto Dst index (geomagnetic storms) and, for the southern hemisphere, the aurora alerts of the Australian Bureau of Meteorology, which require a free key to be entered in the BoM API key box. The AE index (Kyoto) and SuperDARN convection buttons open the two pages in the browser.
LI|The Dst level reads as follows: quiet above -30 nT, weak disturbance between -30 and -50 nT, moderate storm between -50 and -100 nT, intense storm from -100 nT downwards. With the BoM key the Australian K index and the current aurora watch alerts also appear.
LI|Meteor scatter: the chart of today's meteor activity (RMOB data) from Make More Miles on VHF; showers, efficiency and live traffic are in the METEOR SCATTER tab.
P|The summary of these data appears at the top right of the SPORADIC-E and F.A.I. maps (E-skip for the chosen continent) and of the AURORA map (N0NBH aurora and NOAA Bz).
H1|3. Sporadic-E (SPORADIC-E)
P|The SPORADIC-E tab has three sub-tabs: REAL-TIME, the live spots described in this chapter; BENCHMARK Es (chapter 4) and BENCHMARK 50 MHz (chapter 5).
H2|3.1 The map
P|The Map menu chooses the projection. Azimuthal: azimuthal equidistant map centred on your own station, with the zoom slider (from 300 to 20000 km from the centre, also with the mouse wheel). Mercator: the world map, with the Europe and World buttons. In both projections the distance circles of the IK3XTV table [3] are drawn around the station: 500 km (single-hop minimum), 1500-2000 km (optimum), 2400 km (single-hop maximum), 5000 km (double-hop maximum) and 6900 km (triple-hop maximum).
P|The table of hop lengths on 50 MHz is the one by Flavio Egano IK3XTV, «Propagazione sui 6 metri - Caratteristiche generali» (Propagation on 6 metres - General characteristics) [3]; Es clouds lie at a height of about 100 km, and this limits the single hop to around 2000 km [29]. The rings on the maps and the number of hops follow these distances:
TAB|Hop;Minimum distance;Optimum distance;Maximum distance
TAB|Single hop;500-650 km;1500-2000 km;2200-2400 km
TAB|Double hop;2800-3000 km;3200-4000 km;4400-5000 km
TAB|Triple hop;-;4800-6400 km;6900 km
P|In the azimuthal views the dashed rings give the km from the centre; the ring spacing changes with the zoom and the outer edge shows the maximum distance displayed.
H2|3.2 The controls
LI|Bands: 10, 8, 6, 4 and 2 m (432 MHz is not analysed: sporadic-E does not apply [22]-[24]); 8 m (40 MHz) is off by default. Spot time window from 15 minutes to 12 hours.
LI|Es height (110 km by default) and minimum antenna elevation (1° by default); the elevation takes tropospheric refraction into account (Earth radius 4/3), so the single hop reaches about 2440 km.
LI|First hops (equal hops): shows the first hop of both stations; Short first hop within…: shows the author's hypothesis of the short first hop (1200 km by default) [4].
LI|Es clouds on Maidenhead squares: colours the squares of the reflection points according to the highest frequency of the spots (green up to 29 MHz, yellow up to 51, orange up to 71, red up to 145 MHz). If the probable MUF of the cloud on the longest hop (2400 km) reaches a higher band, the square flashes in the colour of that band. For 144 MHz the author's rule applies: the square flashes red only if the cloud gives a 50 MHz hop between 450 and 500 km (450 km with a tolerance of 50 km).
LI|144 MHz towards the Canary Islands, Madeira and the Azores (author's rule): beyond 2400 km the spot counts only if at least two spots point to the same Es cloud; the Es hop, the cloud and the dashed tropo leg to the island are drawn. On 50 and 70 MHz the rule does not apply.
H2|3.3 Tables and details
P|The Es spots table lists the valid spots with distance, number of hops and minimum foEs; the Es clouds (squares) table lists the squares with the estimated clouds and the MUF they would give for your own station (red 144 MHz, orange 70 MHz, yellow 50 MHz). When a zoom is set, the tables show only what is visible on the map.
LI|Columns of the Es spots table: UTC, MHz, DX, Spotter, km, Hops, foEs≥ (estimated minimum foEs) and Prop. Columns of the Es clouds (squares) table: Square, foEs≥, number of spots, azimuth and distance from your own station and My MUF.
LI|Colours and symbols on the map: paths on 10 m green, on 8 m yellow, on 6 m light blue, on 4 m violet and on 2 m orange; small yellow square = midpoint of the single hop; small orange square = first hop of the spotter and small violet square = first hop of the DX (equal hops); small orange circle = short first hop (IC8TEM hypothesis); green circle = range of the single hop from your own station.
LI|Click on a spot in the table or on the map: the path lights up with a yellow halo, the map brings it into view if needed and the Details box gives hops, reflection points, foEs and azimuth. The spot stays selected even when new spots arrive.
LI|Click on an empty point of the map: the point is treated as a possible Es cloud, with the foEs required for 28, 50, 70 and 144 MHz.
LI|With Kp above 3 the map flags it at the top right, as a simple warning: IK3XTV-IZ3ESV [51] find more than 90% of openings with Kp ≤ 3, but on the author's 50 MHz log sporadic-E does not decrease with Kp > 3.
LI|A 50 MHz QSO beyond 11000 km appears in the details as an ALERT, only as a statistical note (EI7GL [56]: HZ1SK-K4MOG, 11460 km).
LI|Multi-hop precursors sub-tab: for distant regions (thirty worldwide) the program checks whether there are active Es clouds, seen from the spots of other stations, on the hop points of the path, with equal hops and always also with the short first hop within 1200 km. ALERT (red): all points covered; PRECURSOR (yellow): only one point missing, in an area without observers. Clicking a row draws the dashed path, the hop points (green: active cloud; grey: no observer; red: no cloud) and the spots that prove the clouds; the details give the foEs required for each hop.
LI|The thirty precursor regions are: Japan, Korea, Eastern China, Philippines, Guam and Marianas, Indonesia, Northern Australia, Eastern Australia, New Zealand, India, Arabian Peninsula, Central Asia, Eastern Siberia, Western Europe, Eastern Europe, Scandinavia, West Africa, Southern Africa, Caribbean, Central America, Mexico, Eastern North America, Central North America, Western North America, Northern Canada, Alaska, Hawaii, Northern South America, Brazil and Southern Cone; those far from your own station are checked. The columns of the table are Level, Region, Band, Hops, Hypothesis (equal hops or short first hop), km and Az°.
LI|Spots in electric blue with the label TEP are paths that cross the magnetic equator but are longer or more asymmetric than pure TEP (for example ZS6 - OH, SM, LA): sporadic-E can couple into TEP. They stay among the Es spots; the Prop column shows ES+TEP.
H2|3.4 The author's rules
LI|144 MHz: sporadic-E starts beyond 900 km; a single spot on its own is not drawn; it is drawn if a second spot on the same cloud arrives within 5 minutes or if there is a short-hop 50 MHz spot nearby. The green line at the top says how many spots are awaiting confirmation.
LI|Trans-equatorial: towards continental Africa (including Madagascar) and South America, if the midpoint falls in the band of magnetic inclination between -15° and +15°, the contact is trans-equatorial and not sporadic-E, unless the spot declares <ES>. The Canary Islands, Madeira, Cape Verde and the Arabian Peninsula are outside the rule. The 15° value is taken from Cracknell [66], who places the TEP zones at about 5-15° from the zero-dip line (author's choice).
LI|50 MHz: within 450 km it is not sporadic-E. FT8 and FT4 spots are sporadic-E only if they are part of a cloud, that is if within 4 minutes there is another 50 MHz spot with its midpoint within 150 km; an isolated FT8 or FT4 spot goes to meteor scatter (author's rule).
LI|70 MHz: within 450 km it is not sporadic-E (author's rule; G0ISW [65] sees the shortest sporadic-E beyond 400 km on 50 and 70 MHz). FT8 and FT4 go to sporadic-E even inside the meteor scatter window of the bandplan.
LI|40 MHz (8 m): the minimum distance is derived from the 450 km of 50 MHz with the secant law (about 330 km) and only distances within the first hop of the E-layer geometry count (about 2440 km).
LI|144 MHz: Q65 and JT65 spots are EME and do not enter sporadic-E, unless <ES> is in the text. G0ISW [65] sees sporadic-E on 144 MHz only beyond 1400 km: the author's rule starts from 900 km but asks for a confirmation.
H1|4. BENCHMARK Es (sub-tab of SPORADIC-E)
H2|4.1 Loading a log
P|The BENCHMARK Es sub-tab is a test bench for sporadic-E on a whole ADIF log, even one from another station. Load ADIF opens the file (the program remembers it and reloads it at startup), Unload ADIF removes it. Station at the centre proposes the most frequent callsign and locator in the log; they can be changed and confirmed with Apply.
LI|The transmitting position is the MY_GRIDSQUARE of each QSO; the receiving positions are the GRIDSQUARE values (missing or 4-character locators are taken from CALL3).
LI|QSOs with another PROP_MODE and those under 500 km (900 km on 144 MHz) can be excluded; trans-equatorial QSOs are always excluded, unless PROP_MODE=ES. The magnetic equator is that of the year of the QSO (historical IGRF-14), as in BENCHMARK 50 MHz.
LI|On the map a blurred yellow dot marks the centre of every hop, where the sporadic-E cloud is presumed to be (also the centre of the short first hop, if that hypothesis is on).
H2|4.2 Days, hours and calculations
P|The QSOs per day table lists the days with number of QSOs, bands, maximum distance and multi-hops; clicking on a day fills the Hours of the day table, with one row for each UTC hour and the Whole day row. The azimuthal map, with the maximum distance slider, draws the skip by 10° sectors (orange arc = nearest QSO, green sector = distances reached), the clouds on the squares and, for the whole day, the hourly drift of the clouds (red line).
P|The Proposed calculations page gives the skip by sectors, the estimated foEs with the expected MUF at 1000, 1500, 2000 and 2400 km, the estimated clouds, the multi-hop check (equal hops versus short first hop, compared with the clouds seen on single hop within ±30 minutes) and the drift of the clouds hour by hour.
LI|Table columns: QSOs per day (Day, QSO, Bands, km max, Multi-hop); Hours of the day (UTC time, QSO, km min - max, Multi-hop, Bands): clicking an hour shows the QSOs of that hour, with UTC, Callsign, Locator, MHz, km, Hops and foEs≥. Clicking a QSO highlights it on the map with the first hop of the correspondent. The summary also says how many trans-equatorial QSOs have been excluded.
H1|5. BENCHMARK 50 MHz (sub-tab of SPORADIC-E)
H2|5.1 One or two stations
P|The BENCHMARK 50 MHz sub-tab is devoted to multi-hop sporadic-E on 50 MHz. In the Station 1 row you load and unload the log of your own station; in the Station 2 row the log of a second station, which is shown or hidden with the Station 2 checkbox. The paths of station 1 are light blue, those of station 2 violet.
LI|Multi-hop 50 MHz QSOs are shown, that is beyond 3100 km (author's rule); the number of hops follows the IK3XTV table.
LI|Day, from… to… UTC: the day (on opening, the one with the most multi-hop QSOs) and the time, in steps of 15 minutes.
LI|foEs (optional): colours the paths with the minimum foEs and gives it in the table. Es height and Short first hop within 1200 km as in the other tabs.
LI|The blurred yellow dot marks the centre of every hop, where the sporadic-E cloud is presumed to be; on the path under the mouse it becomes larger.
LI|The table lists the QSOs shown with St. (station 1 or 2), Day, UTC, Callsign, WWL, km, Hops and foEs≥. With foEs on, the hop points give the minimum foEs; a 4-character locator missing from CALL3 is flagged next to the WWL.
H2|5.2 The Mercator map
P|The map is a Mercator projection with a free centre. When the mouse approaches a path, the line and icons are enlarged and the 6-character WWL square of the correspondent appears. With a left click on that path a popup asks whether to show all the QSOs in the file, from all days, with the end position within 150 km: Yes clears the map and shows those QSOs inside the orange circle, No leaves the map as it is. The Back to day and time button returns to the previous selection.
H1|6. F.A.I.
H2|6.1 The two views
P|The F.A.I. tab studies scatter from field-aligned irregularities (main source [1], [2]). The Scatter trail (A-B pair) view calculates, for two stations, the locus of possible scatter points, coloured according to the deviation from the reflection condition, proposes the most probable scatter point and draws at the top right the box of QTFs and elevations of both stations (red = A, green = B). The Isoflection (point) view draws, for a chosen reflection point, the isoflection lines like AuroReflex and SE-PROP by K9SE: coloured bands in the dark schemes, thick lines in the light schemes.
H2|6.2 The controls
LI|Station A and Station B: callsign (looked up in CALL3) and/or locator; A empty = your own station. The Checks… menu loads the test pairs (IC8FAX-F6DRO, IC8FAX-G4LOH, IC8FAX-FA1MXE, DL5MCG-SV1DH of 1987 via Budapest); the two dated cases (1990 and 1987) are calculated with the IGRF-14 field of that year, written in the map caption, as long as the stations remain those of the case; the Known scatter points… menu selects a documented scatter point (Geneva, Brussels, Budapest, JN92, JN41/42).
LI|Height (110 km by default), minimum elevation and Refraction (4/3 Earth radius), on by default.
LI|The view menu chooses between Scatter trail (A-B pair) and Isoflection (point). In the Isoflection view the contour lines are at 0, ±1, ±2, ±4, ±8 and ±16 degrees of deviation; the 0 line is the locus of the stations that receive A through the chosen point.
LI|Left click on the map: reflection point to be checked (switches to the Isoflection view); right click: position of station B.
LI|Check the recommended point: calculates the trail, takes the proposed scatter point and shows its isoflection lines with the verdict: SATISFACTORY (within 1°), ACCEPTABLE (within 2.5°), NOT SATISFACTORY (beyond).
LI|The results of the Scatter trail view give the most probable scatter point (6-character locator, coordinates and deviation), for each station QTF, elevation and distance, and the magnetic inclination at the point; if the trail passes close to a known scatter point, they say so. On the map the box at the top right gives the QTFs: A in red, B in green.
LI|Equipment (DL5MCG [6]): F.A.I. on 144 MHz needs at least a long yagi and 100 W (SV1DH was also worked with an 8-element yagi and 50 W). The antenna is pointed at the scatter point given by the program, not at the correspondent.
P|If the calculation is not possible for the model, the message Calculation not possible appears and no other result is shown. At the bottom the F.A.I. spots table lists the spots declared FAI; clicking on a spot loads its pair of stations.
LI|The F.A.I. spots on the map and in the table are those of the period chosen in the SETTINGS filters (24 hours by default); the table gives UTC, MHz, DX, Spotter, km and Comment.
H1|7. METEOR SCATTER
P|The tab contains the complete YA-MS program, with its tabs (Live and real-time data: live meteor scatter traffic, radar flux, GRAVES radar; Forecast calculation: celestial sphere and calculation, geometry and attenuation, efficiency calculation, experimental implementation of the forecasts; Technical documents: showers, sources, map of the sources, explanation of the efficiency calculation, user manual, squares map) and its calculation manual. Language and colour scheme are those chosen at the top. Inside E-LAYER ANALYZER the YA-MS Data collection does not appear: there is only one data collection, that of DATA COLLECTION, which passes the lines to YA-MS, and the meteor scatter spot filter is set in the filter column of DATA COLLECTION.
P|YA-MS 1.8.1 treats the antenna lobe as a vertical pattern («antenna pattern» box, on by default): the reflection points are weighted with the vertical gain of both antennas and the efficiencies no longer vanish on long paths. It adds the «no common zone» warning, highlights the β angle box (the choice that weighs most), uses a single calculation date, brings the «User manual» and the comparison with 181,767 real spots on 50 MHz from the HamSCI Meteor Scatter QSO Party of August 2025: the hours and the sides of the path are reliable, the percentages are indicative.
P|From version 0.5.0 the tab contains YA-MS 1.8.15: a single column next to the Forecast calculation map (correspondent with the antenna heading and legend); in Live traffic my station, radius and projection and the spot details in boxes above the map, the Mercator map that moves by dragging it (double click: back to the station) and the active PSKReporter monitors; isolated FT8 spots checked with PSKReporter MQTT, FT8 on 28 MHz removed, «shower zone» and «% shower» instead of the cloud; «Save» button to store a different locator of the correspondent in CALL3; forwarding of MS decodes to PSKReporter via UDP and encrypted exchange between YA-MS users of the messages addressed to their own station. The YA-MS Settings tab keeps the live sources, RMOB and the command lines; font, colour scheme, language and updates are chosen in the SETTINGS tab of E-LAYER ANALYZER. Spot collection remains a single one, that of DATA COLLECTION.
H1|8. AURORA
P|The AURORA tab uses the same views as F.A.I. (default height 110 km, Lange-Hesse [12]) with NOAA space weather data [15]: the OVATION auroral oval (shaded on the map), the Kp index of the last three days and the solar wind, downloaded every 5 minutes into data/swpc or at once with Download NOAA now. The program recommends the beam heading for both stations.
LI|Controls specific to the tab: the Auroral oval (NOAA OVATION) checkbox, on by default, shades the oval on the map and uses it as a weight in the choice of the scatter point; Download NOAA now updates the data at once. The Space weather (NOAA SWPC) box shows the chart of the planetary Kp of the last 3 days, every 3 hours, and the time of the oval and of the last download. The Scatter trail and Isoflection views are used as in F.A.I. (chapter 6), with a tolerance of 3°.
LI|Aurora spots from the period chosen in the SETTINGS filters (by default the last 2 hours, 30 at most) are drawn on the map with the calculated scatter point (orange circle) if the <AU>/<AUR> spots on the map with the calculation checkbox is on; the results show the QTF and elevation of the two stations.
LI|The results of the Scatter trail view show the aurora probability at the scatter point (unlikely with Kp ≤ 2; otherwise according to the NOAA oval), the typical QTF between N and NE (S-SE in the southern hemisphere) with the deviation from the direct path, and advice on Doppler and modes (CW/SSB or Q65 with wide submodes: FT8 often does not decode). The scatter point is preferably searched inside the Lange-Hesse window of each station, with perpendicularity within ±3°: 370-1100 km at 54° geomagnetic latitude, closer for stations further south and farther for those further north, according to the IGRF-14 inclination (for example Capri about 260-990 km, Oslo 470-1200 km). The results show the window of each station; if the proposed point is outside it, the program flags it.
LI|The aurora probability at the scatter point is decided in this order: unlikely with Kp ≤ 2, except during a storm (Dst ≤ -50 nT); in the southern hemisphere likely with a BoM aurora alert; likely with Dst ≤ -100 nT and possible with Dst ≤ -50 nT, if the oval at the point is not zero; likely with the oval from 10%; possible with the oval from 3% or with Kp ≥ 5; otherwise unlikely.
LI|Aurora spots beyond 2000 km are flagged as doubtful: according to Newton [48], aurora reaches around 1000 km north-south and 2000 km east-west. Auroral E spots (AUE, AU-E, AURORAL E) are drawn in green on the direct path: this is sporadic E of auroral origin, without Doppler.
LI|The results show the solar time at the scatter point: most auroral reflections fall within 4 hours of local midnight (Reeve [52]). In the southern hemisphere aurora on 50 MHz reaches up to about 2000 km on east-west paths (ANVDG [55]); auroral E gives weaker and steadier signals on the direct path (SM2CEW-SM0FOB [54]).
LI|In addition to the most likely scatter point, the results show the QTF range of the two stations along the whole trail (deviation ≤ 1.5°): aurora can come from any point of the range, and the most likely point gives preference to the shortest path.
H2|8.1 BENCHMARK AURORA

LI|The Log menu chooses one log or all of them together; the default height is 110 km, with tolerance 3°, 4/3 refraction and IGRF-14 of the year of each QSO (historical epochs 1900-2030; with the date unknown, today's field).

Green: scatter point inside the Lange-Hesse window of both stations; yellow: explained but outside this window; orange: QSO beyond 2000 km; red: no scatter point, QSO not explained by the model.
LI|The Height km box changes the height of the calculation (from 80 to 160 km) and recalculates all the QSOs. The columns of the table are Day, UTC, Callsign, WWL, km, Scatter, dev°, QTF and el° of the log station, Corr. QTF (the QTF of the correspondent) and Result. The Details of the selected QSO box gives distances, beam headings, the Lange-Hesse window of each station and the deviation from the direct path.
LI|The summary gives the percentages, also with the fixed 370-1100 km window for comparison, and, for each log, the range and median of the computed QTF; clicking a row draws the path and the two beam headings and shows the window of each station. H2|10.2 Spot routing
P|On the left a table lists the rules with which the program decides where each spot goes, in the order in which they are applied: the first one that applies decides the tab. The values shown are those set in the filters. On the right are the local filter and the filters of each mode, in five sub-tabs.
P|At the top is the local filter checkbox, on by default: "DX de" lines with a frequency below 27990.0 kHz or above 145 MHz are dropped, do not appear in the console and are not stored; between 430 and 440 MHz only aurora spots pass. It is useful above all with RBN and PSKReporter, which send a great many HF spots. With the checkbox off everything passes. Below are five sub-tabs.
LI|Meteor scatter: the YA-MS filter (frequency windows typical of MS, tags of other propagation, MS digital modes and <MS>, bands, filter test and counters). Inside E-LAYER ANALYZER the YA-MS filter is set in the METEOR SCATTER tab and applies only to that tab.
LI|Sporadic-E: the tags between < > that exclude a spot from sporadic-E; the 28, 40, 50 and 70 MHz rules (on 50 and 70 MHz within 450 km it is not sporadic-E; on 40 MHz from about 330 km up to the first hop, about 2440 km; FT8 and FT4 on 50 MHz only if they are part of a cloud; on 28 MHz the minimum distance is derived from the 50 MHz one following IK3XTV, about 170 km; the bandplan is not an exclusive criterion, so a spot in the meteor scatter window stays in sporadic-E unless it has the MS digital mode or <MS>); the 144 MHz rule (minimum distance; confirmation by a second spot on the same cloud within a few minutes, or by a short-hop 50 MHz spot nearby) and the trans-equatorial rule with its magnetic dip band, which applies to Africa and South America (the author's rule) and, worldwide, to 3000-8000 km contacts that cross the magnetic equator in a nearly north-south direction (Kennewell and Wilkinson [49]). The Restore the author's rules button brings back the default values.
LI|Default values of the sporadic-E rules, all editable: minimum distance on 50 and 70 MHz 450 km; FT8 and FT4 on 50 MHz with another spot within 4 minutes and midpoint within 150 km; 144 MHz rule on, with minimum distance 900 km and confirmation within 5 minutes by a second spot on a cloud within 300 km, or by a 50 MHz spot from the last 15 minutes with a short hop up to 1200 km; trans-equatorial rule on, with the magnetic inclination band of ±15°.
LI|F.A.I.: the words that mark a F.A.I. spot (FAI by default: <FAI> or fai counts, in upper, lower or mixed case; these spots do not enter sporadic-E), the bands (6, 4 and 2 m: F.A.I. does not reach 432 MHz) and the period of the spots on the map (24 hours by default).
LI|Aurora: the words of aurora spots, with or without < > and in upper or lower case (AU and AUR by default), the bands and the period of the spots on the map (2 hours by default).
LI|Filter test: you type or paste a cluster line and the program shows how the filters classify it (meteor scatter, aurora, F.A.I., trans-equatorial, sporadic-E), with band, locator and distance.

H1|12. Practical tips
LI|First of all enter your callsign and locator at the top and press Apply: all distances, MUFs and elevations start from there.
LI|With RBN and PSKReporter keep the local filter on, so as not to fill the memory with HF spots.
LI|To analyse a past season, use the two BENCHMARK tabs with your own log; for aurora and F.A.I. always check the proposed point with the Isoflection view.
LI|The calculations are indicative: a spot or a QSO tells you that the path was open, not exactly where the cloud was.
H1|13. Frequent problems
LI|NTP:FAILED: no time server has answered. Usually a firewall blocks the port UDP 123; the program carries on with the PC clock and tries again every 5 minutes.
LI|The telnet session does not connect or closes at once: check host, port and login (many clusters want the callsign) and that no other session is already open with the same callsign, for example from another program.
LI|No spots in SPORADIC-E: check the bands and the time window chosen, that the local filter does not discard the band (it lets through from 27990 kHz to 145 MHz, and between 430 and 440 MHz only aurora) and, on 144 MHz, that the spot has a confirmation (section 3.4). The Filter test (SETTINGS, Spot routing) tells how a cluster line is classified.
LI|Empty maps at the first start: coastlines and borders are downloaded from GitHub the first time; a network connection is needed, then they stay in data/mappa.
LI|LoTW refuses access: check user name and password on the LoTW website; with large logs the download can take a few minutes.
LI|The automatic update does not start or fails: check the network and that the program folder is writable; with the .deb, .rpm, Arch and Slackware packages it does not start on purpose. In any case, from the release page you can install the new version by hand over the old one, without losing the data folder.
